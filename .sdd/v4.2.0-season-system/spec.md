# V4.2.0 季节系统 — 需求规格（spec.md）

> 版本：V4.2.0 · 主题：春、夏、秋、冬四季系统
> 状态：基于已写好但未集成的 `SeasonCatalog` / `SeasonState` 核心类，完成 9 个集成点接入、测试、存档迁移与版本号变更。
> 范围声明：本规格仅描述「做什么（WHAT）」，不含实现细节。

---

## 1. 背景与目标

Infinite Frontier 是 Godot 4.7 的 2D 俯视角程序化无限世界生存探索 RPG，完全离线。V4.1.0（commit 5378a44，6475 PASS / 0 FAIL）已提交。V4.2.0 引入四季系统，使世界随游戏天数在春、夏、秋、冬之间循环，并影响温度、植物颜色、农作物生长、天气选择、河流冻结、资源产出、敌人数量与季节事件。

核心数据模型 `data/season.json`、`scripts/season/season_catalog.gd`、`scripts/season/season_state.gd` 已写好但**未集成、未测试、未提交**。本版本的目标是把这些核心类接入既有系统、补齐自动测试、完成存档迁移与版本号变更，使季节系统成为可玩、可验证、不破坏旧存档的完整功能。

---

## 2. 范围边界

### 2.1 本版本做

- 将 `SeasonState` 接入昼夜/天数驱动源（`DayNightCycle.snapshot()["day"]`）。
- 将季节属性接入 9 个既有系统：生存温度、天气权重、河流冻结、作物生长、植物颜色、敌人数量、资源产出、存档、版本号。
- 为季节核心类与集成行为补充自动测试。
- 完成存档格式 26→27 迁移（旧档初始化空季节状态，day=1）。
- 更新版本号至 4.2.0 / save 27 / generation 7。
- 更新 README、CHANGELOG、开发日志、save-format.md。

### 2.2 本版本不做

- 不重新设计已写好的 `SeasonCatalog` / `SeasonState` 核心 API。
- 不引入季节过渡动画的视觉淡入淡出（`transition_days` 配置项保留但本版本不实现过渡渲染）。
- 不引入新的季节专属敌人种类、季节专属资源种类、季节专属作物种类（仅调整既有内容的倍率/权重/冻结）。
- 不引入网络、生成式 AI、外部二进制依赖。
- 不混入 V4.3.0+ 内容（如季节专属事件剧本、季节成就）。
- 不改变既有生成字节以外的生成契约（仅河流冻结改变生成字节，故 generation version +1）。
- 不主动推送 GitHub。

## 3. 功能需求

### 3.1 季节核心数据（已存在，本版本仅校验）

| ID | 需求 | 验收标准（EARS） |
|----|------|------------------|
| FR-1 | 四季配置加载 | **当** `SeasonCatalog` 加载 `data/season.json` **时**，系统 **应当** 返回 `is_valid()==true` 且 `season_count()==4`，四季 ID 依次为 `spring`、`summer`、`autumn`、`winter`。 |
| FR-2 | 季节时长 | **当** 查询 `season_duration_days()` **时**，系统 **应当** 返回 8；**当** 查询 `transition_days()` **时**，系统 **应当** 返回 1。 |
| FR-3 | 天数→季节映射 | **当** `SeasonState` 的 day 为 1 **时**，季节 **应当** 为 spring；day 9 **应当** 为 summer；day 17 **应当** 为 autumn；day 25 **应当** 为 winter；day 33 **应当** 循环回 spring。 |
| FR-4 | 季节属性查询 | **当** 查询各季节的 `temperature_offset`、`plant_tint`、`river_freezes`、`crop_growth_multiplier`、`resource_yield_multiplier`、`enemy_population_multiplier`、`weather_weight` **时**，系统 **应当** 返回 `data/season.json` 中对应配置值。 |
| FR-5 | 季节状态快照 | **当** 调用 `SeasonState.snapshot()` **时**，系统 **应当** 返回包含 `schema_version=1`、`day`、`season_id`、`season_index` 及全部季节属性的字典。 |
| FR-6 | 季节持久化 | **当** 调用 `persistence_snapshot()` 后 `restore_snapshot()` **时**，系统 **应当** 完整恢复 day 且季节属性重新派生一致。 |

### 3.2 集成点需求（9 个）

| ID | 集成系统 | 需求 | 验收标准（EARS） |
|----|----------|------|------------------|
| FR-7 | 昼夜/天数驱动 | 季节由游戏天数驱动 | **当** 昼夜循环推进使 `DayNightCycle.snapshot()["day"]` 变化 **时**，季节状态 **应当** 同步推进到对应季节。 |
| FR-8 | 生存温度 | 季节温度偏移叠加到目标温度 | **当** 环境字典包含季节信息 **时**，`SurvivalCatalog.target_temperature()` **应当** 在群系/天气/昼夜偏移之上再加季节 `temperature_offset`。 |
| FR-9 | 天气权重 | 季节调整天气选择概率 | **当** 天气系统选择天气 **时**，系统 **应当** 将季节 `weather_weights` 与群系权重相乘后归一化选择，使冬季更易出现雪、夏季沙漠更易出现沙暴。 |
| FR-10 | 河流冻结 | 冬季河流冻结为冰湖 | **当** 季节 `river_freezes==true` 且地形为河流 **时**，`HydrologyGenerator.feature_at()` **应当** 返回 `Feature.ICE_LAKE` 而非 `Feature.RIVER`。 |
| FR-11 | 作物生长 | 季节倍率影响作物生长速度 | **当** 农作物推进生长 **时**，生长增量 **应当** 乘以季节 `crop_growth_multiplier`（夏季 1.3、冬季 0.3 等）。 |
| FR-12 | 植物颜色 | 季节色调混合植物颜色 | **当** 渲染植物/群系颜色 **时**，系统 **应当** 用季节 `plant_tint` 与群系 `color` 混合（春季嫩绿、秋季金黄、冬季灰白）。 |
| FR-13 | 敌人数量 | 季节倍率影响敌人候选数量 | **当** 敌人生成规划器产生候选 **时**，候选数量 **应当** 乘以季节 `enemy_population_multiplier`。 |
| FR-14 | 资源产出 | 季节倍率影响资源产出 | **当** 资源产出计算 **时**，产出数量 **应当** 乘以季节 `resource_yield_multiplier`。 |
| FR-15 | 存档兼容 | 旧存档可迁移到新格式 | **当** 加载 save format 26 的旧存档 **时**，系统 **应当** 迁移到 format 27，初始化空季节状态（day=1，即春季），且保留全部既有玩家/世界/差分状态。 |

### 3.3 季节事件（轻量）

| ID | 需求 | 验收标准（EARS） |
|----|------|------------------|
| FR-16 | 季节切换通知 | **当** 季节从一季切换到下一季 **时**，系统 **应当** 通过事件总线发出季节状态变更通知，含新季节 ID 与显示名。 |

## 4. 非功能需求

| ID | 需求 | 验收标准（EARS） |
|----|------|------------------|
| NFR-1 | 离线运行 | **当** 游戏运行 **时**，季节系统 **不得** 发起任何网络请求或依赖外部二进制。 |
| NFR-2 | 确定性 | **当** 同一种子与同一游戏天数 **时**，季节状态 **应当** 完全确定且可复现。 |
| NFR-3 | 存档不破坏 | **当** 加载 V4.1.0 及更早存档 **时**，系统 **不得** 丢失或篡改任何既有玩家、世界、差分状态。 |
| NFR-4 | 性能 | **当** 季节状态查询 **时**，单次查询 **应当** 在 O(1) 时间内完成，不引入逐帧开销。 |
| NFR-5 | 类型安全 | **当** 季节属性在 GDScript 中传递 **时**，**不得** 使用 `Variant` 无类型变量或 `any` 等价物；所有公开 API **应当** 有明确返回类型。 |
| NFR-6 | 配置校验 | **当** `data/season.json` 缺失四季之一、duration 非正或天气权重和为零 **时**，`SeasonCatalog` **应当** 返回 `is_valid()==false` 并给出可读错误信息。 |

## 5. 测试需求

| ID | 需求 | 验收标准（EARS） |
|----|------|------------------|
| TR-1 | 核心模型测试 | **当** 运行测试套件 **时**，`_test_season_models()` **应当** 验证：SeasonCatalog 加载校验、四季 ID、duration、天数→季节映射（day 1/9/17/25/33）、各季节温度偏移/河流冻结/作物倍率值正确、存档 round trip。 |

| TR-3 | 全绿门 | **当** 运行 `tools/run_tests.sh` **时**，全部测试 **应当** 通过（0 FAIL），既有 6475 项不回归。 |
| TR-4 | 版本契约 | **当** 运行 `tools/verify_project.py` **时**，版本断言 **应当** 通过 4.2.0 / 27 / 7。 |

## 6. 存档兼容性需求

| ID | 需求 | 验收标准（EARS） |
|----|------|------------------|
| SR-1 | 格式升级 | **当** V4.2.0 保存新世界 **时**，`world.json` 与 `player.json` 的 `save_version` **应当** 为 27，`generation_version` **应当** 为 7。 |
| SR-2 | 迁移路径 | **当** 加载 format 2–26 的旧存档 **时**，系统 **应当** 接受并迁移到 27，初始化空季节状态（day=1）。 |
| SR-3 | 季节持久化 | **当** 保存含季节状态的世界 **时**，`world.json` **应当** 包含 `season_state` 字段（schema_version=1，day）。 |
| SR-4 | 迁移不发明 | **当** 迁移旧存档 **时**，系统 **不得** 发明季节进度（始终 day=1）、不得改变既有差分、不得改变既有玩家位置/库存/进度。 |
| SR-5 | 生成版本 | **当** 河流冻结改变生成字节 **时**，`generation_version` **应当** 从 6 升至 7；format 6 及更早生成版本 **应当** 仍可加载并迁移。 |

2. NFR-1 ~ NFR-6 全部满足。
